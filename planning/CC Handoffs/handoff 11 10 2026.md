## 1. Goal
Build **Demanufacture**, a NeoForge 1.21.1 compat mod for the user's modpack ("New'O'Nautics", later their SMP). The user's complaint: the mods each have their own ecosystem and don't harmonise. Demanufacture connects them.

**Now (decided 2026-10-07):** a general **pack harmoniser**. Three mechanisms keep coming up:
1. **Machine / recipe-type adapters:** machine A also runs recipe type B (for example the TFMG Chemical Vat running `create:mixing`). Read at runtime, configurable by datapack. Details: `../ideas/Pack Scan - Compat Features.md` section 8.
2. **Shared standards:** one fuel table, one `c:crude_oil` tag, one set of electricity conversion rates, one price table. See `../ideas/Electricity Audit.md`.
3. **Targeted bridges** between two mods (for example worn Pixel Backpacks into YAGM graves).

**Cooking module (frozen):** an Overcooked-style overhaul linking **Farmer's Delight (FD)** and **Kaleidoscope Cookery (KC)**: instead of waiting for a pot, you prepare the meal in a minigame per cook block; the result gets a generated name, backstory and quality, recorded in a cookbook. Original vision: cookbook item toggles **cook mode**; basket (FD) is ingredient storage shown beside every minigame; free-form action chains; long term in-world camera. Decisions made for it: hand-cooking stays **optional and fun** (not a quality gate); dish quality will **write into KC's own `QUALITY` component** (Superb / Excellent / Standard / Poor) instead of our five tiers.

### 4c. Mind map technical notes (for editing the canvases programmatically)
- Plain JSON canvas. Card ids are short slugs (`kc`, `tfmg`, `bpixel`, `yagm`, `irons`, `cogs`, `tacz`...). Hub ids are `hub_<category>` (`hub_food`, `hub_industry`, `hub_guns`...). Centre card id is `center`.

Colours `"1"` and `"4"` are **reserved for cross arrows**; hubs use 2, 3, 5, 6.
- Layout was produced by simulated annealing with these rules: **at least 220 px between any two cards**, arrows must not pass through cards, minimise crossings, avoid arrows leaving a card at almost the same angle; arrow sides are chosen from the card's aspect ratio. Last measured (2026-10-09, after the removals): Similar 1 crossing, Connect 23, full map 94 (with 0 arrows through cards, 0 cards too close).

### 10d. Blockbench workflow (this took a long time to get right)
- The user models/animates in **Blockbench 5.x (flatpak)**. Project files are `ArtificeCannons/blockbench/<gun>.bbmodel` (Bedrock format, v5 JSON with a `groups` array and `outliner` of uuids). **The user often has the project open elsewhere or saves it without noticing**, so always check `ls -l` of the project file AND the newest autosave.
- **Autosaves** live in `~/.var/app/net.blockbench.Blockbench/config/Blockbench/backups/backup_D.M.YY_H.M_<name>.bbmodel`, written every 10 min and only when changed. They are **lz-compressed**: file starts with `<lz>`, then `LZUTF8` with `inputEncoding: 'StorageBinaryString'` (npm `lzutf8`). Decode with node.
- **Export rules** (verified against Blockbench itself): geometry x is mirrored (`origin_x = -to_x`, pivots negate x), cube rotation `[-x, -y, z]`; up/down faces export `uv=[x2,y2]`, `uv_size=[x1-x2, y1-y2]`; animation values are stored **internally** flipped: export `rotation = [-x, -y, z]`, `position = [-x, y, z]` (scale unchanged). Groups/cubes with `export:false` are skipped (used for the arm reference boxes).
- **Arm convention (important):** in game the `left_arm`/`right_arm` bone **pivot is the hand**; the arm extends back toward the player along local +Y. The reference boxes must be `from [-2,0,-2] to [2,12,2]`. Old boxes (-12..0) mean the poses are in the shoulder-pivot convention and need conversion: `new_position = position + R(rotation) * (0,-12,0)`, same rotation. The five current projects use the new convention.
- **Timing rule:** every bone must have a final keyframe at the animation length returning to rest, or it holds the last pose and snaps back. Check last keyframe vs rest before export, and `reload` seconds x 20 = gun reload ticks.
- The scripts that did import/export (`bbtool.py`: fix_arms, export_geo, export_anim; `makegun.py`: Java item model -> bbmodel with baked rotated UVs) lived in the session scratchpad and are **gone** after a reboot. The rules above are enough to rebuild them. Java face UV rotation cannot be stored in Bedrock, so rotated faces are baked into extra texture rows (texture height grows).
- IANA reads: `geo/item/<registryname>.geo.json`, `animations/item/<registryname>.animation.json`, `textures/item/<registryname>.png` under the item's namespace. Animations played: `idle` (hold), `fire`, `reload`, `equip`. Special bones: `root`, `gun`, `left_arm`, `right_arm` (empty bones, the player's arm model is drawn at the pivot), `attachment_muzzle`, `hammer*`, `magazine`, `ramrod`.

### 10e. IANA internals learned (jar decompiled with Vineflower, see section 3 for the tool)
- Guns are Java `GunItem(GunProfile)`; profile from `GunProfile.builder(capacity, slots, reloadTicks, FireMode{SEMI,AUTO}, ArmPoseKind{PISTOL,RIFLE}, ShotComponentTemplate)`. No data-driven path.
- `ShotComponentTemplate.builder(damage, spread, characterBlowback, fireDelayTicks, RecoilProfile)`; `.bulletSpeedMultiplier`, `.projectileCount`, `.gravity`, `.gunshotSound(Supplier<GunShotSoundStack>)`, `.muzzleFlash`.
- **Bullet damage = clamp(|velocity per tick|, 0..2)/2 x DAMAGE / projectileCount.** Default speed 12 per tick, gravity 0.05. DAMAGE is the total across pellets.
- Events on `NeoForge.EVENT_BUS`: `AmmoEvent.Amount` (set rounds per shot), `GunAboutToShootEvent` (cancellable), `GunShootEvent.Pre/Post`, `BulletImpactEvent`, `ComposeShotEvent`. `GunplayManager.tryFire`, `FireDelayState`, `ReloadState` are public.
- **The client fires first**: `InputHandler` runs `tryFire` locally, applies camera recoil and sends `ServerboundFireGunPacket`. A server-only veto produces a phantom shot (recoil, no sound). Any lock must be mirrored on the client (BurstBehaviour does).
- The animation packet is `ClientboundGunAnimationPacket(entityId, geoId, hand, anim, speed, offsetSeconds, skipAt, skipTo)` (public); `ClientHelper.playClientGunAnimation` applies it. Speed exactly 0 snaps to frame 0; use a tiny speed to freeze.
- `GeoItem` model ids are the item registry key; IANA sets `gun.geoRenderProvider` for every `GunItem` in `RegisterRenderers`.
